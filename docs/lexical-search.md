# Лексический поиск

Change `lexical-search-index` плана [2.0](development-plan-v2.md):
`code_crawler.search.search_text` и MCP-инструмент `search_text` — нечёткий поиск
по именам сущностей, когда точное имя неизвестно. Точный поиск символа по имени и
сигнатуре остаётся в [структурном поиске](structural-search.md).

## Что ищется

Имена сущностей типов SYMBOL, SOURCE_FILE, DATABASE_OBJECT, ORM_MAPPING, ORM_QUERY;
для символов — ещё и полное имя. Тексты SQL и связи в этот индекс не входят.

Идентификатор нормализуется функцией `ucm_identifier_words`: делится на слова по
смене регистра и по не-буквенно-цифровым знакам и приводится к нижнему регистру.
`findUserById`, `find_user_by_id` и `app.Repo.load` дают `find user by id` и
`app repo load`. Запрос нормализуется так же.

## Ранжирование

Каждый результат несёт `match` и `similarity` (триграммное сходство имени с запросом):

1. `EXACT` — запрос равен имени или полному имени без учёта регистра;
2. `WORDS` — все слова запроса есть в имени или полном имени (PostgreSQL FTS,
   конфигурация `simple`, без стемминга и стоп-слов);
3. `SIMILAR` — похожее написание или подстрока (`pg_trgm`), ловит опечатки.

Внутри группы — по убыванию `similarity`, затем по имени и ID: порядок
детерминирован.

## Фильтры и страницы

`search_text(conn, repository_key, query, *, entity_types, snapshot_id, limit, offset)`

- `repository_key` обязателен; по умолчанию читается опубликованный snapshot.
- `snapshot_id` выбирает другую версию того же репозитория, но только бывшую
  опубликованной (PUBLISHED или RETIRED); BUILDING, VALIDATING и READY отклоняются.
- `entity_types` — подмножество пяти типов выше.
- `limit` 1–200, `offset` 0–1000. Ответ содержит `truncated` и `next_offset`
  (`null`, когда страниц больше нет).

## Индексы (миграция 0019)

Миграция ставит расширения `pg_trgm` и `btree_gin` (оба из разрешённого списка) и
создаёт три GIN-индекса, каждый начинается с `snapshot_id`, поэтому цена поиска не
растёт с числом хранимых версий:

| Индекс | Назначение | Размер на 124 тыс. сущностей |
| --- | --- | --- |
| `ucm_entities_name_trgm_idx` | триграммы `lower(name)`, частичный по пяти типам | 944 kB |
| `ucm_entities_name_words_idx` | слова имени, частичный по пяти типам | 408 kB |
| `ucm_symbols_qualified_words_idx` | слова полного имени символа | 824 kB |

На нагрузочном наборе из [query-indexes.md](query-indexes.md) (локальный
PostgreSQL 18) запрос занимает 4–33 мс; время полной индексации осталось в
пределах шума (55 с).

## Ограничения

- Слова сравниваются целиком: `op` не находит `op3`, префиксного поиска нет.
- Граница буква/цифра слова не делит: `Service107` — одно слово `service107`.
- Короткие запросы (1–2 символа) почти не дают триграмм и находят только точные
  совпадения и слова.
- `unaccent` не применяется: он не immutable и не годится для индекса по выражению.
