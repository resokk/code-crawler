# Слой данных

Legacy-структура прикладной БД хранится отдельным слоем — не внутри графа кода и не в индексах репозиториев. Слой один на всё хранилище: запросы из разных репозиториев ссылаются на одни и те же таблицы.

Описание слоя строится из двух источников:

1. **Структура в БД** — читается из системного каталога прикладной PostgreSQL командой `schema import`. Реализовано.
2. **Прикладные annotations из JSON** — дополнение legacy описания, формат ещё не задан.

Независимый canonical schema manifest и versioned inventory реализованы отдельно:
[database-identity.md](database-identity.md). Они различают database/schema/version
и не заменяют legacy слой командой импорта.

## `code-crawler schema import`

Читает структуру прикладной БД и заменяет ею слой данных — целиком, в одной транзакции.

```bash
export SOURCE_DATABASE_URL=postgresql://user:password@host:5432/app   # прикладная БД
export DATABASE_URL=postgresql://user:password@host:5432/crawler      # хранилище индексов
uv run code-crawler schema import
```

- Прикладная БД только читается.
- Берутся все несистемные схемы: таблицы (включая секционированные), представления, материализованные представления, внешние таблицы.
- Для каждой колонки сохраняются тип, обязательность, вхождение в первичный ключ и комментарий; для таблицы — комментарий; отдельно — внешние ключи по колонкам.
- По завершении печатается число таблиц и представлений, колонок и внешних ключей.

## Таблицы слоя

Миграция `0002_data_layer.sql`.

| Таблица | Содержимое |
| --- | --- |
| `data_tables` | `schema`, `name`, `kind` (`table`, `view`, `materialized view`, `foreign table`), `comment` |
| `data_columns` | `table_id`, `name`, `position`, `data_type`, `nullable`, `primary_key`, `comment` |
| `data_foreign_keys` | `name`, `column_id` → `ref_column_id` |
| `data_refs` | ссылки из кода на слой данных |

## Ссылки из кода

Индексатор не создаёт узлов таблиц и колонок. Для каждого запроса он пишет в `data_refs` ссылки по имени. В PL/Plus ссылки идут ещё и от операций и файлов ЦФТ: стандартная операция `NEW_AUTO` вставляет в таблицу своего класса, а присваивание `[РЕКВИЗИТ] := …` пишет в его колонку (см. [indexing.md](indexing.md)).

| `kind` | На что | `attrs` |
| --- | --- | --- |
| `reads` | таблица | `access: read` |
| `writes` | таблица | `access`: `insert`, `update`, `delete`, `merge`, `ddl` |
| `uses` | колонка | `roles`: `select`, `where`, `join`, `group`, `order`, `having`, `write` |

`table_name` — имя в нижнем регистре так, как оно написано в запросе: `users` или `app.audit`.

Ссылки хранятся по имени, а не по идентификатору, поэтому слой данных и индексы репозиториев обновляются независимо и в любом порядке: `schema import` не требует переиндексации, а индексация не требует загруженной структуры.

Сопоставление ссылки с таблицей слоя при чтении:

- имя со схемой (`app.audit`) — по точному совпадению схемы и имени;
- имя без схемы (`users`) — по имени таблицы в любой схеме;
- ссылка на таблицу, которой в слое нет (временная таблица, опечатка, структура ещё не загружена), остаётся несопоставленной.
