# Решение

ParseResult сохраняет внутренний Tree (исключён из repr/equality), поэтому новый java_symbols adapter использует тот же AST после diagnostics и legacy extraction, а не разбирает bytes повторно. SourceInput hash проверяется перед формированием фактов. Result содержит FileAnalysis, parser diagnostics и Coverage; SourceFile предоставляет orchestrator.

Первый проход создаёт FILE/TYPE/CALLABLE/BLOCK scopes и Symbol для named types, explicit methods/constructors, formal parameters, fields и обычных locals. Class key основан на FQN, callable key использует class key, name и ordered syntactically erased parameter names. Constructors называются <init>, post-name dimensions и varargs учитываются. Parameter Symbol хранит полный syntactic TypeRef, signature — syntactic generic erasure. Полная JLS erasure, type variables/import aliases не заявляются. Duplicate keys не сливаются.

Local keys основаны на lexical scope, block keys — на структурном ordinal, method IDs не зависят от body offsets. Второй проход создаёт declaration/read/write/reference/call occurrences по точным AST token ranges. Nearest lexical binding учитывает local visibility с конца имени declaration. this.field ищется в ближайшем TYPE, произвольный receiver не подменяется текущим классом. Compound assignment/update создаёт READ+WRITE. Named type references остаются UNRESOLVED.

Method name occurrence имеет CALL, но единственный одноимённый метод не доказывает applicability. Несколько локальных overloads сохраняются AMBIGUOUS candidates в REFERENCES Relation; CALLS edges не создаются. DECLARATION получает DECLARES с точным target/Evidence, остальные usages — REFERENCES с явными Resolution/Certainty/Coverage. Lexical reference имеет INFERRED certainty, не runtime proof.

Неподдерживаемые lambda/catch/enhanced-for/resources/switch/method-reference/anonymous-class/annotation-element поддеревья исключены. Callable body с pattern bindings и pattern-containing initializer пропускаются, чтобы не связать неизвестную shadowing declaration с полем. Record components и compact constructors пока не моделируются. Coverage всегда PARTIAL с версиями/причинами. Некорректная parameter list не превращается в вымышленную нулевую сигнатуру.

extract возвращает partial facts и diagnostics для явного caller review. analyze_files, используемый incremental API, отклоняет parser diagnostics: текущий FileAnalysis storage ещё не сохраняет их, поэтому молчаливая публикация была бы неверной. Legacy CLI продолжает прежний partial recovery с persisted diagnostics. Callback здесь только java.symbols capability, SQL facts добавит следующий SQL adapter; он не заменяет полный legacy index/compatibility projection.

Storage уже поддерживает все модели: migrations не нужны. End-to-end test проверяет COPY, readiness restore, publication, новые local refs, стабильные method IDs и reuse второго файла. При parser error прежний published snapshot сохраняется. Cross-file linking/dependencies будут расширены java-call-resolution с новым analysis profile.
