# Решение

Отдельный модуль `tests/test_baseline_regressions.py` использует публичные функции `java.parse`, `sql.analyze`, `indexer.build`, `indexer.register`, `repos.resolve`, `repos.files` и `repos.head`.

Java/SQL fixtures встроены в тесты. Файлы создаются только в `tmp_path`. Dirty worktree проверяется на настоящем временном Git-репозитории: локальный commit создаётся исключительно как тестовая fixture, затем tracked-файл изменяется и добавляется untracked-файл. Сеть, модели и настоящая БД не используются. Конфликт регистрации проверяется с `AsyncMock`; ограничения PostgreSQL этим не проверяются.

Известные дефекты имеют префикс `legacy` и точные assertions текущего результата. Не используем широкие xfail, которые могли бы скрыть новые ошибки. Исправление дефекта закономерно потребует обновления baseline assertion.

Ограничения: отсутствие диагностики AST, неоднозначная идентичность перегрузок и таблиц, ложный executes и конфликт basename остаются открытыми. Тесты фиксируют эти ограничения, но не исправляют их.
