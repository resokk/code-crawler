# PostgreSQL integration

## ADDED Requirements

### Requirement: Изолированная PostgreSQL 15 база
Каждый тест SHALL работать в собственной временной БД и удалять её после завершения.

#### Scenario: Явное подключение
- GIVEN TEST_DATABASE_URL к PostgreSQL 15 с CREATEDB.
- WHEN запускается тест.
- THEN создаётся уникальная БД, которая удаляется в teardown.

#### Scenario: Не настроена интеграция
- GIVEN TEST_DATABASE_URL отсутствует.
- WHEN запускается pytest.
- THEN integration tests явно skipped, обычные тесты выполняются.

### Requirement: Проверяемая история миграций
#### Scenario: Инициализация и повтор
- GIVEN пустая БД.
- WHEN проверяется статус, затем дважды применяется init.
- THEN сначала получена ошибка неинициализированной БД, затем все миграции учтены и повтор безопасен.

#### Scenario: Неизвестная миграция
- GIVEN актуальная БД с записью неизвестной миграции.
- WHEN начинается migrate.
- THEN получена ошибка «БД новее кода».

#### Scenario: Ошибка после DDL
- GIVEN миграция с CREATE TABLE и ошибочным SQL.
- WHEN она применяется.
- THEN новая таблица и запись миграции отсутствуют, прежняя история сохранена.

### Requirement: COPY сохраняет атомарность индекса
#### Scenario: Загрузка, сбой и замена
- GIVEN два зарегистрированных репозитория и граф Java/SQL.
- WHEN графы загружаются, затем COPY одного репозитория падает на NOT NULL.
- THEN прежние узлы и commit этого репозитория сохранены.
- WHEN его граф заменяется пустым.
- THEN его узлы и зависимые связи удалены, граф второго репозитория сохранён.

### Requirement: CLI работает с настоящей БД
#### Scenario: Полный локальный цикл
- GIVEN пустая БД и локальный Git-репозиторий с Java-файлом.
- WHEN отдельные процессы вызывают status, init, повторный init, migrate, status и дважды index.
- THEN первый status возвращает 1, остальные команды 0; в БД один репозиторий, три узла без дублей и правильный commit.
