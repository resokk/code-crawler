# Решение

Pytest marker `integration` выделяет набор; без TEST_DATABASE_URL тесты явно пропускаются. Указанный URL используется только как административное подключение для CREATE/DROP DATABASE. Каждому тесту создаётся уникальная БД crawler_test_<uuid>, после теста она удаляется с FORCE. DATABASE_URL пользователя не используется как fallback. Нужен PostgreSQL major 15 и пользователь с CREATEDB; неверная версия или отказ подключения приводят к ошибке, а не skip.

Асинхронные сценарии запускаются через asyncio.run, без новых зависимостей. CLI запускается отдельным Python-процессом с тестовым DATABASE_URL. Java fixture и локальный Git commit создаются в tmp_path. Сеть к Git-хостингам и модели не нужны.

COPY проверяется через реальный indexer.store: узлы, связи и data_refs, JSONB, откат после NOT NULL violation, замена пустым графом и сохранность второго репозитория. Ошибка миграции проверяется временным SQL-файлом с DDL и намеренной ошибкой в одной транзакции.

Ограничения: базовая схема пока не использует расширения; их доступность этот набор не подтверждает. Внешний PostgreSQL предоставляется разработчиком или CI. Docker не является зависимостью самих тестов.
