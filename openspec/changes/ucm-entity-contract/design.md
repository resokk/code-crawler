# Решение

Используем Pydantic, уже установленный через FastMCP; закрепляем прямую зависимость через uv add, поскольку новый модуль использует его API. Это заменяет ручную рекурсивную проверку, сериализацию и построение схемы.

Модели frozen, extra=forbid, strict=True. EntityEnvelope содержит версию, scope репозитория, логический ключ, EntityType, ID, имя и необязательную source location. SourceFile добавляет типизированные path, language, content_sha256. CodeEntity допускает только три базовых типа. EntityDocument использует дискриминатор entity_type, экспортируемая схема сохраняется как docs/ucm-entity.schema.json.

SHA-256 от канонического JSON-массива исключает коллизии конкатенации компонентов. Repository ID задаёт вызывающая сторона, а не имя каталога; ID не включает snapshot, номер строки или hash содержимого. SourceFile использует path как logical_key. Кодировки и формат ID нормативно описаны в docs/ucm.md.

SourceRange использует полуоткрытые координаты (1-based line, 0-based UTF-8 byte column). Отсутствие координат не заменяется нулевыми значениями. Python проверяет порядок и вычисляемую идентичность; JSON Schema выражает структурные ограничения. Существование source_file_id и границы файла требуют будущей batch validation. Конвертер не должен придумывать точные byte columns из legacy line-only данных.

На данном шаге модели не утверждают достоверность SQL execution и не вводят произвольные attrs. Регистры будут расширяться последующими changes с проверкой совместимости.
