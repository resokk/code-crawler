# Решение

JavaSymbolsResult сохраняет внутренний extractor/AST (исключён из equality/repr), а extractor — declaration nodes. java_calls переиспользует эти данные, не меняя legacy extraction. JavaCallAnalyzer принимает immutable SourceInput одного репозитория, строит catalog named types/methods/imports/modifiers и возвращает FileAnalysis для requested файлов.

Поддержаны method_invocation в explicit method/constructor, unqualified/this receivers, lexical data variables с известным declared type, explicit static class receivers, single-type/static imports и chains с resolved return type. Catalog не смешивает default-package одноимённые типы с текущим package. Local type shadowing не разрешается как одноимённый member/global type. Classpath/wildcards/generic bounds остаются неопределёнными.

Argument descriptors выводятся из scalar literals, declared identifiers/this fields, casts/new, parenthesized выражений и supported nested calls. Проверяются arity, static receiver/context и базовая private/package visibility. Применимость поддерживает exact types, primitive widening и reference→Object. Победитель обязан доминировать по каждому conversion position, не по сумме ranks/порядку объявления. Unknown conversion остаётся неизвестной; null, boxing, varargs expansion, generics и сложные reference conversions не угадываются. Наследование и runtime dispatch вне coverage.

CALLS связывает caller Symbol с declared Method. Unique supported target имеет RESOLVED/INFERRED/PARTIAL Coverage; это не runtime callee proof. AMBIGUOUS/PARTIAL сохраняют typed candidates без target. CALL Occurrence и его REFERENCES Relation обновляются согласованно; PARTIAL occurrence отображается UNRESOLVED, поскольку его прежний контракт не имеет PARTIAL. Initializer/constructor-invocation и исключённые поддеревья не получают подтверждённых CALLS.

Неизвестная цель без local named candidates сохраняется ExternalReference с exact invocation Evidence и локальной EXTERNAL_DEPENDENCY. Selector signature остаётся неизвестной, argument types не выдаются за declaration signature. External resolution всегда UNRESOLVED; другие repository indexes не читаются. Ошибка parser или stale captured bytes останавливает canonical callback.

analysis_version включает fingerprint types, source paths, package/imports, method IDs/signatures/return types/modifiers/varargs и inheritance flags. Изменение catalog инвалидирует все Java files, включая прежние unresolved callers при появлении нового type. Body-only changes не меняют catalog profile и используют обычную dependency closure. Явные file dependencies добавляются для receiver classes, а structural target refs выводятся прежним orchestrator. index_incremental проверяет optional required analyzer profile, чтобы caller не обошёл fingerprint простой константой.

index_java создаёт analyzer из полного capture и запускает incremental writer. Новый snapshot не публикуется автоматически. Текущая подготовка catalog разбирает все Java sources; output reuse остаётся incremental, но parser-cost optimization/persisted catalog потребуют отдельного расширения. Generic incremental API для остальных adapters не меняет своей selective-parse семантики. Legacy CLI/compatibility projection остаются прежними.

Storage модели и schema уже поддерживают новые facts; migration не требуется. End-to-end PostgreSQL tests проверяют Controller→Service→Repository, transitive invalidation, catalog addition resolution, ambiguous/partial/external roundtrip и profile gate. Coverage всегда честно PARTIAL.
