# Решение

UcmBatch — immutable Pydantic модель с repository UUID и tuple всех Entity типов. Batch замкнут относительно локальных ссылок: файлы координат/evidence, scopes/owners/parents, occurrence targets, TypeRefs, operation values, relation targets/candidates и ExternalReference sources проверяются по одному каталогу. Проверяются duplicate IDs, duplicate paths, scope parent cycles и множественные producers. Foreign repository entities запрещены. Модели при подготовке повторно разбираются из JSON, чтобы не доверять model_construct/model_copy.

Подготовка normalized records выполняется asyncio.to_thread. SourceFile, CodeEntity, Symbol/signature, Scope, Occurrence, Operation, Value, Relation и ExternalReference поддерживаются полностью текущей схемой 0004. Все структурные данные раскладываются по типизированным колонкам, не в JSON batch blob. Value literal использует JSON scalar; для LITERAL null — JSON null, для остальных видов — SQL NULL. Selector unknown/zero-parameter distinction сохраняется. Relation candidates сохраняются как множество: их порядок контрактом storage не определён.

ingest_batch принимает свободное соединение, snapshot UUID и полный batch. В собственной транзакции он блокирует snapshot FOR UPDATE, проверяет repository/state/пустоту. Concurrent writers одного snapshot сериализуются; проигравший видит заполненный snapshot и получает ошибку, разные snapshots грузятся независимо.

Для каждой непустой группы records создаётся уникальная TEMP TABLE LIKE canonical INCLUDING DEFAULTS ON COMMIT DROP. COPY заполняет staging, pass 1 вставляет все envelope IDs в ucm_entities, pass 2 — extensions и вспомогательные таблицы. Deferred FKs позволяют ссылки вперёд и циклическое owner/scope. SET CONSTRAINTS ALL IMMEDIATE проверяет ссылочную целостность до commit. Уникальные staging names строятся только из UUID и внутренних имён таблиц; пользовательский ввод не становится SQL identifier.

Каноническая схема уже использует logical ID в составном ключе, поэтому mapping logical ID→(snapshot UUID,entity ID) не требует выдачи surrogate sequences. Staging является session-local и исчезает при commit/rollback. Ошибка COPY, canonical INSERT, FK или cancellation откатывает загрузку целиком. Snapshot остаётся BUILDING, pointer не меняется; retry в том же пустом snapshot допустим. Успешно заполненный snapshot не принимает повторную полную загрузку. Empty batch допустим.

Persistent schema migration не нужна: используются существующие колонки 0004 и temporary DDL. Writer держит batch и records в памяти; крупные streaming batches и durable job telemetry остаются ограничениями. Границы source ranges по исходным bytes и истинность evidence не проверяются, поскольку batch хранит только fingerprint. State/publication gate — следующий change 11. Внешний indexer и legacy CLI не меняются.
