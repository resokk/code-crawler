# AGENTS.md

## Проект

**code-crawler** — MCP-сервер с GraphRAG по коду: обходит кодовую базу, строит граф знаний (файлы, символы, связи между ними) и отдаёт его агентам через инструменты MCP для поиска и ответов на вопросы о коде.

Конвейер: обход исходников → разбор и извлечение сущностей и связей → граф + эмбеддинги → запросы GraphRAG → инструменты MCP.

Две точки входа:

- **MCP-сервер** — отвечает на запросы по готовым индексам.
- **CLI** — отдельный инструмент для управления индексами (создание, обновление, удаление, просмотр).

Сервер и CLI используют общий код работы с индексами, а не дублируют его.

## Стек

- Python 3.12+
- `uv` — зависимости и запуск
- `fastmcp` — MCP-сервер, транспорт Streamable HTTP в режиме stateless
- `transformers` — модели эмбеддингов
- `torch` — инференс моделей
- `asyncpg` — драйвер PostgreSQL
- `tree-sitter` — разбор Kotlin, Java, TypeScript, JavaScript, Python; грамматика каждого языка — отдельный пакет `tree-sitter-<язык>`
- ANTLR 4.13.2 (`antlr4-python3-runtime`) — разбор Groovy, PL/Plus и VBScript; грамматики в `grammars/`, сгенерированные лексеры и парсеры лежат в репозитории
- `sqlglot` — разбор SQL (диалект PostgreSQL)
- `rich` — вывод CLI: прогресс и статус операций
- `pytest` — тесты
- `ruff` — линтер и форматтер

Ещё не выбрано (решить до первой реализации и вписать сюда): конкретная модель эмбеддингов.

## Хранение

PostgreSQL 15 — единственное хранилище: и граф, и векторы, и текстовый поиск.

Расширения, уже установленные в БД:

- `vector` 0.8.0 — эмбеддинги, индексы HNSW и IVFFlat
- `pg_trgm` 1.6 — нечёткий поиск по именам символов и путям
- `ltree` 1.2 — иерархии (путь файла, вложенность модулей и символов)
- `unaccent` 1.1 — нормализация текста для поиска
- `pg_cron` 1.6.1 — задания по расписанию

Доступны, но не установлены (нужен `CREATE EXTENSION`): `rum`, `btree_gin`, `btree_gist`, `hstore`, `citext`, `pgcrypto`, `uuid-ossp`, `intarray`, `bloom`, `fuzzystrmatch`.

Правила:

- Использовать только расширения из этих списков. Других на сервере нет, и поставить их нельзя.
- Графового расширения (Apache AGE) нет. Граф хранится в обычных таблицах узлов и рёбер, обход — рекурсивными CTE.
- Индекс HNSW в `vector` 0.8.0 принимает векторы до 2000 измерений (`halfvec` — до 4000). Модель эмбеддингов выбирать с учётом этого.
- Схему менять только миграциями в репозитории, не руками в БД.

## Команды

```bash
uv sync                 # установить зависимости
uv run pytest           # тесты
uv run ruff check .     # линтер
uv run ruff format .    # форматирование
```

## Правила

- Минимальный диф, который полностью решает задачу. Никаких абстракций, опций и конфигов «на будущее».
- Сначала стандартная библиотека и уже установленные зависимости. Новую зависимость добавлять только через `uv add` и только если она заменяет заметный объём кода.
- Аннотации типов на всех публичных функциях.
- Ввод-вывод (сеть, диск, БД) — асинхронный; внутри `async`-кода не блокировать цикл событий.
- Инструменты MCP: понятное имя, описание в docstring, типизированные аргументы. Аргументы — это внешний ввод: проверять их, а пути ограничивать корнем индексируемого репозитория.
- Сервер stateless: каждый HTTP-запрос самодостаточен. Не хранить состояние сессии в памяти процесса между запросами и не полагаться на то, что следующий запрос попадёт в тот же процесс. Всё, что должно пережить запрос, лежит в хранилище.
- Индексы изменяет только CLI. Сервер их только читает.
- Модели и индексы загружаются один раз при старте процесса, а не на каждый запрос.
- Нетривиальная логика (парсер, построение графа, запросы) идёт вместе с тестом. Тесты не ходят в сеть и не зовут настоящие модели.
- Секреты — только из переменных окружения, в репозиторий не попадают.
- Перед коммитом: `uv run ruff check . && uv run pytest`.
- Комментарии — только «почему», если этого не видно из кода.
- Коммиты и пуши — только по просьбе пользователя.
